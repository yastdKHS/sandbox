# 保守マニュアル

対象読者: 本ツールのVBAコードを保守・拡張するエンジニア。

## 1. モジュール構成と責務

| モジュール | 責務 | 依存先の目安 |
|---|---|---|
| mod_Common | シート名・テーブル名・列名・画面レイアウト定数、汎用ヘルパー、共通エラーハンドラ | なし（最下層） |
| mod_Logging | T_Log への書き込み・自動間引き | mod_Common, mod_Settings |
| mod_Database | スキーマ初期化（EnsureSchema）、T_Scores/T_Summary の CRUD、総合評価再計算 | mod_Common, mod_Settings, mod_Logging |
| mod_Settings | T_Items/T_Settings/T_Templates のアクセサ | mod_Common, mod_Database, mod_Logging |
| mod_Import | データ取込ウィザードの業務ロジック | mod_Common, mod_Database, mod_Settings, mod_UI, mod_Logging |
| mod_Statistics | 統計計算の純粋関数（副作用なし） | mod_Common のみ（実質独立） |
| mod_Analysis | 分析画面のデータ抽出・統計計算呼び出し・グラフ更新の司令塔 | mod_Common, mod_Database, mod_Settings, mod_Statistics, mod_Graph, mod_UI |
| mod_Graph | 分析画面の3グラフの系列更新 | mod_Common, mod_Statistics |
| mod_UI | 画面構築（フォームコントロール生成）、ボタン等のイベント振り分け | ほぼ全モジュール（表示層として最上位） |

依存関係は概ね一方向（mod_Common → 各データ層 → mod_Analysis/mod_Import →
mod_UI）であり、循環依存を避けている。ただし VBA の標準モジュールは
相互参照可能であるため、コンパイル上の制約はない。

## 2. ソースからブックを再構築する

`vba/build/BUILD_README.md` を参照。要点は以下の通り。

- VBAソース（`.bas`）を正として管理し、`.xlsm` はビルド成果物として扱う。
- `vba/build/modBuildTool.bas` の `BuildWorkbook` マクロを実行すると、
  ソース一式のインポート → 画面構築（`mod_UI.SetupAllSheets`）→
  `.xlsm` として保存、が自動で行われる。
- 画面が壊れた場合は、完成した `.xlsm` を開いた状態で
  マクロ実行ダイアログ（Windows: `Alt+F8` ／ Mac: [ツール]-[マクロ]-
  [マクロの表示]）から `SetupAllSheets` を実行すれば、データを保持したまま
  画面（ボタン・リストボックス・グラフ）だけを再構築できる。
- ビルド作業自体はWindows版Excel 2019のほか、Windows版／Mac版
  Microsoft 365 Excelでも可能（詳細は `vba/build/BUILD_README.md`）。
  完成した `.xlsm` はExcel 2019標準機能のみで構成されているため、
  どの版で開いても同じ挙動になる。

## 3. 評価項目数を増やす／変更する

**コード変更は不要です。** `T_Scores` が縦持ち（1行=1学生×1評価項目）で
あるため、データ取込時に新しい列を「新規評価項目」としてマッピングするだけで
`mod_Settings.GetOrCreateItem` が自動的に `T_Items` へ項目を追加します。
表示名・重みは「設定」画面から編集できます。

## 4. 画面レイアウトを変更する

`mod_Common` の `IMP_*` / `ANL_*` / `SET_*` / `DB_*` / `LOG_*` / `HOME_*` /
`NAV_*` 定数がセル位置・コントロール名を一元管理しています。
レイアウトを変更する場合は、これらの定数のみを書き換え、
`mod_UI.SetupAllSheets`（または該当画面の `SetupXxxSheet`）を再実行してください。
コントロールの生成ロジック（`mod_UI` の `AddButtonControl` 等の共通ヘルパー）
自体は変更不要です。

## 5. よくある拡張ポイント

- **列マッピングテンプレートの自動適用**: 現状はテンプレートの保存・削除・
  一覧表示のみを実装しており、次回インポート時に自動でマッピングへ
  反映する機能は未実装です（`mod_Settings.LoadTemplateMapping` が
  マッピング文字列を返すため、`mod_Import.ConfirmSheetSelection` の
  マッピング候補生成部分に、テンプレート一致時の優先適用ロジックを
  追加することで拡張できます）。
- **シート保護**: `docs/02_シート設計書.md` に記載の通り、v1.0では
  意図的に導入していません。追加する場合は `mod_UI` の各
  `SetupXxxSheet` 内で入力対象セル以外を `.Locked = True` にし、
  `ws.Protect Password:=..., UserInterFaceOnly:=True` を呼び出してください
  （`UserInterFaceOnly:=True` を指定することで、VBAからのセル書き込みは
  保護に影響されず動作します）。
- **CSVエクスポート等の出力機能**: 現状は分析結果の画面表示のみです。
  必要になった場合は `mod_Analysis` が保持する集計配列を元に、
  新しい `mod_Export` モジュールを追加する形が適切です（既存モジュールの
  責務を汚さないため）。

## 6. コーディング規約

- 全モジュールで `Option Explicit` を必須とする。
- シート名・テーブル名・列名・コントロール名は必ず `mod_Common` の
  定数を経由する（直接の文字列リテラルを禁止）。
- 各 Public プロシージャは `On Error GoTo ErrHandler` を持ち、
  `ErrHandler` 内で `mod_Common.HandleError` を呼び出す
  （ログ記録とメッセージ表示を一元化するため）。
- ワークシート関数は `Application.WorksheetFunction.関数名` または
  `Application.関数名` を明示的に使用する。**VBAの言語仕様には
  `Round` 関数が存在しない**（Excelのワークシート関数として提供される）
  ため、`Application.Round(値, 桁数)` のように必ず修飾すること。
  これは実際に開発時に検出・修正した典型的な落とし穴である。
- `IIf` 関数は真偽どちらの分岐も無条件に評価される（短絡評価されない）。
  配列の範囲外アクセスやゼロ除算の可能性がある式を分岐に含める場合は、
  `IIf` を使わず通常の `If ... Else ... End If` を使用すること。
- **`vba/modules/*.bas` と `vba/ThisWorkbook.txt` は Shift-JIS（CP932）・
  改行CRLF固定で保存する（UTF-8にしないこと）。** 日本語版WindowsのVBEは
  `.bas` インポート時にファイルの文字コードをANSI（Shift-JIS）として
  読み込むため、UTF-8のまま保存すると日本語コメント・文字列が文字化けし
  コンパイルエラーになる（詳細は `vba/build/BUILD_README.md`）。
  UTF-8既定のエディタで編集する場合は、保存時に必ずエンコーディングを
  Shift-JISへ明示的に変更すること。

## 7. トラブルシューティング

| 症状 | 確認事項 |
|---|---|
| インポート/ビルド時にコード中の日本語が `竭｢ 險ｭ螳�` のような文字化けになりコンパイルエラーになる | `.bas`/`ThisWorkbook.txt` がUTF-8で保存されている（Shift-JISになっていない）。
  リポジトリのファイルをShift-JISで保存し直してから再インポートする |
| ボタンを押しても反応しない | マクロが有効化されているか確認。マクロ実行ダイアログ
  （Windows: `Alt+F8` ／ Mac: [ツール]-[マクロ]-[マクロの表示]）で対象マクロが
  一覧に表示されるか確認（表示されない場合はモジュールの
  インポート漏れの可能性） |
| 画面のボタン・グラフが消えた/崩れた | 同ダイアログから `SetupAllSheets` を実行して再構築する |
| 取込時に「ファイルを開けませんでした」と表示される | 元ファイルが破損していないか、対応形式（.xlsx/.xlsm/.xls）か確認 |
| 総合評価が意図した値と異なる | 「設定」画面の重み設定を確認し、「反映」ボタンで再計算する。
  「データベース」画面の「再集計・更新」でも全件再計算できる |
| ログが増え続けて心配 | `T_Settings!LOG_MAX_ROWS` の値を確認（既定5000件で自動間引き） |
| ビルド時に「VBAプロジェクトへのアクセスが拒否されました」等のエラー | Windows: トラストセンターで「VBA プロジェクト オブジェクト モデルへの
  アクセスを信頼する」が有効か確認する。Mac: 同設定が無い/効かない場合は
  `vba/build/BUILD_README.md` の手動ビルド手順（.basを1つずつインポート）を使う |

## 8. 動作確認について

本プロジェクトは、Excel実行環境を持たないLinux開発環境で作成された
VBAソースです。コード上の整合性（未定義参照・型の不一致等）は
静的なチェックを行っていますが、**実際のExcel 2019上での動作確認は
未実施**です。`vba/build/BUILD_README.md` の手順でビルドした後、
本ドキュメント末尾のセルフレビュー（`08_セルフレビュー.md`）に記載の
確認項目に沿って、必ず実機での動作確認を行ってください。

# シート設計書

## 1. シート一覧

| シート名 | 種別 | 可視性 | 用途 |
|---|---|---|---|
| ホーム | 画面 | 表示 | メニュー・ダッシュボード |
| データ取込 | 画面 | 表示 | 取込ウィザード |
| 分析 | 画面 | 表示 | 分析条件選択・グラフ・統計表 |
| 設定 | 画面 | 表示 | 評価項目マスタ・各種設定・テンプレート管理 |
| データベース | 画面 | 表示 | 学生別総合評価一覧・容量管理（削除） |
| ログ | 画面 | 表示 | 操作・エラーログ一覧 |
| D_Scores | データ | 非表示（xlSheetVeryHidden） | 評価点数の実データ（縦持ち） |
| D_Templates | データ | 非表示（xlSheetVeryHidden） | 列マッピングテンプレート |

D_Scores・D_Templates は `xlSheetVeryHidden` に設定しており、
Excelの「再表示」メニューからも表示されない（VBAからのみアクセス可能）。
一般利用者が誤って内部データを編集・削除することを防ぐための措置である。

設定・データベース・ログの3画面は、内部テーブル（T_Items / T_Settings /
T_Summary / T_Log）を**画面シート自身の上に直接配置**している。
別に非表示のデータシートを持たないのは、以下の理由による。

- コピーを持たないため、更新時の同期処理（コピー⇄表示の一致確認）が不要になり
  保守すべきコードが減る。
- 容量が単純にテーブル1個分で済み、長期利用時の肥大化を抑えられる。
- 利用者が「設定」「データベース」「ログ」画面で見ている内容がそのまま
  実データであるため、表示の齟齬が原理的に発生しない。

## 2. シート保護方針

v1.0では、シート保護（セルロック）は意図的に導入していない。
理由は以下の通り。

- 評価項目の表示名・重み、詳細設定値、マッピング表、削除対象指定など、
  多数のセルが利用者による直接入力の対象であり、保護を導入すると
  ロック範囲の管理が複雑化し、誤ってロックした結果「編集できない」
  問い合わせが増えるリスクがある。
- ボタン操作を中心としたワークフローになっており、誤操作によるセル破壊の
  リスクは相対的に低い。

将来的にシート保護を追加する場合は `mod_UI` の `SetupXxxSheet` 内で
入力セル以外を `.Locked = True` にした上で `ws.Protect` を呼び出す形で
拡張できる（`docs/07_保守マニュアル.md` 参照）。

## 3. 命名規則

- 可視シート名は日本語の画面名（例:「データ取込」）とし、`mod_Common` の
  `SH_xxx` 定数で参照する。
- 非表示データシート名は `D_` プレフィックスを付与する。
- テーブル（ListObject）名は `T_` プレフィックスを付与する。
- コントロール名は種別プレフィックス＋画面略称＋機能名とする
  （例: `btnImpCommit` = ボタン／データ取込画面／登録）。

## 4. 行・列の予約

各画面シートの1行目はナビゲーションバー専用、2行目はタイトル専用として
全画面で統一している。3行目以降を各画面固有のコンテンツに使用する。
これにより、どの画面を開いても操作の起点が同じ位置にあり、
VBAに詳しくない利用者でも迷わない。
